# Tool Confirmation Design

## 目标

为本地 Tool Agent 增加一套最小的“人工确认”机制。低风险文本工具保持自动执行；模拟敏感工具必须先得到用户确认，才允许执行。

本阶段只模拟保存笔记，不创建、修改或删除任何真实文件。

## 范围

新增一个 `save_note(text)` 工具。它返回模拟保存成功的文字，作为将来真实写文件工具的安全练习入口。

工具分为两类：

| 类别 | 工具 | 执行方式 |
| --- | --- | --- |
| 低风险 | `upper_text`、`count_words`、`summarize_text` | 模型请求后直接执行 |
| 需要确认 | `save_note` | 先等待用户确认，再执行模拟操作 |

## 状态与流程

`LLMToolAgent` 新增 `pending_tool_call` 状态。它保存等待用户批准的工具名称、参数和 `tool_call_id`。

```text
普通请求
  -> 模型请求低风险工具
  -> Python 直接执行
  -> 结果回传模型

保存笔记请求
  -> 模型请求 save_note
  -> Python 保存 pending_tool_call
  -> 返回确认提示，不执行工具
  -> 用户输入“确认”
  -> Python 直接执行 save_note（模拟）
  -> 清空 pending_tool_call 并返回结果
```

确认与取消由 Python 处理，不再发送给模型。这保证“确认”只会批准当前等待中的那一次操作，而不会被模型当作普通聊天内容。

## 交互规则

1. `save_note` 被请求时，Agent 返回明确的确认提示，包含将要模拟保存的文本。
2. 有待确认操作时，用户输入 `确认`，Agent 执行该工具，返回成功结果并清空状态。
3. 有待确认操作时，用户输入 `取消`，Agent 清空状态并返回取消提示。
4. 没有待确认操作时输入 `确认` 或 `取消`，Agent 返回“当前没有待确认的操作”。
5. 有待确认操作时输入其他内容，Agent 不调用模型、不执行工具，并提示用户输入 `确认` 或 `取消`。

## 同轮多工具规则

如果同一模型响应同时包含 `save_note` 和其他工具，本阶段拒绝整个批次，不执行其中任何一个工具。原因是当前确认状态只能安全地表示一项待确认操作；拒绝整批可避免部分已执行、部分待确认的难以解释状态。

原有“单次请求最多执行三次工具调用”的上限保持不变。等待确认的 `save_note` 在获批准前不计入已执行次数。

## 模块职责

### tools.py

- 新增 `save_note(text)`；只返回模拟保存结果。
- 新增或维护工具风险元数据，使 Agent 能判断哪些工具需要确认。

### llm_agent.py

- 将 `save_note` 加入工具 Schema 和工具注册表。
- 初始化 `pending_tool_call`。
- 在 `run()` 开始处优先处理确认、取消和待确认状态。
- 遇到需要确认的工具时保存待确认信息并返回，不执行该工具。
- 拒绝混合了需确认工具的同轮批次。

### test_llm_agent.py

- 验证 `save_note` 需要确认且第一次不执行。
- 验证确认后执行并清空状态。
- 验证取消、无待确认确认/取消、待确认时其他输入。
- 验证混合工具批次被整体拒绝，且没有工具被执行。

### README.md

- 说明工具风险分级、确认/取消命令和“模拟操作不写文件”的边界。

## 错误与安全边界

- 保留既有的工具白名单、JSON 解析和 `text` 类型校验。
- 不记录或执行真实系统命令，不读写真实文件。
- 若待确认调用的数据非法，返回既有参数错误，不进入执行阶段。
- 每个确认只能消费一项保存的待确认操作；成功或取消后必须清空状态，防止重复执行。

## 验收标准

1. 旧测试持续通过。
2. `save_note` 首次请求只产生确认提示，不产生模拟保存结果。
3. 输入 `确认` 后才产生模拟保存结果，且不会额外调用模型。
4. 输入 `取消` 不执行工具并清空状态。
5. 混合同轮批次不执行任何工具。
6. 全量 `pytest -q` 通过，`git diff --check` 无检查错误。
