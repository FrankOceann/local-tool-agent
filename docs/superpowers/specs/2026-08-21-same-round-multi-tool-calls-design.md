# 同一轮多工具调用 Agent 设计

## 目标

将 `LLMToolAgent` 从“每一轮只接受一个工具调用”升级为“每一轮可接受多个工具调用”。

模型可以在同一次响应中请求多个互不依赖的本地工具。Python 按模型给出的顺序逐个校验和执行工具，再把每个工具结果都交回模型，由模型生成回答或决定下一轮工具调用。

## 范围

- 保留三个工具：`upper_text`、`count_words`、`summarize_text`。
- 保留单次用户请求最多执行三次工具调用的总上限。
- 支持同一轮返回多个工具调用，但不使用线程或并行执行。
- 工具按模型返回的顺序依次执行。
- 任一工具校验或执行失败时立即停止，并向用户返回已有中文错误信息。
- 不新增联网、文件访问、记忆、新工具或真正并发执行。

## 运行流程

```text
用户请求
  ↓
带工具 Schema 调用模型
  ↓
模型直接回答？──是──→ 返回回答
  │否
  ↓
本轮工具调用数量是否超过剩余额度？──是──→ 返回上限错误
  │否
  ↓
按模型顺序逐个：校验 → 执行 → 记录 tool 结果
  ↓
所有工具成功？──否──→ 立即返回错误
  │是
  ↓
达到三次总上限？──是──→ 不带工具 Schema 请求最终回答
  │否
  ↓
再次带工具 Schema 调用模型
```

例如，模型可以在一轮中返回：

```text
upper_text("hello") → "HELLO"
count_words("I am learning") → 3
```

Python 依次执行它们，并分别将两个结果与各自的 `tool_call_id` 加入消息历史。之后模型可使用这两个结果生成最终回答。

## 实现设计

### `llm_agent.py`

`LLMToolAgent.run()` 继续维护 `messages` 和工具总执行次数。

1. 每次带 Schema 的模型响应可以包含一个或多个 `tool_calls`。
2. 先计算本轮调用数是否超过 `MAX_TOOL_CALLS - 已执行次数`；超过时不执行任何工具，返回新的上限错误消息。
3. 将模型的 assistant 消息追加到 `messages` 一次。
4. 遍历本轮的 `tool_calls`：每个调用都复用 `_run_tool()` 做白名单、JSON 与 `text` 类型校验。
5. 每个成功结果都追加一条独立的 `role="tool"` 消息，且保留该调用自己的 `tool_call_id`。
6. 任一调用返回错误时，立刻停止；不执行该轮剩余工具，也不再请求模型。
7. 本次请求累计执行三次工具后，发起一次不含 `tools` 和 `tool_choice` 的最终模型请求。

增加常量错误信息，用于工具总上限不足以容纳当前整批调用的场景。该错误必须清楚说明“单次请求最多执行 3 次工具调用”。

### 工具调用约束

- `tool_calls` 为空：直接返回模型文本。
- `tool_calls` 非空但本轮数量超过剩余额度：拒绝整批调用，不执行其中任何工具。
- 未知工具、无效 JSON、缺失或非字符串 `text`：保持现有错误信息，立即停止。
- 同一轮多个合法工具：按原有顺序执行，不保证并发或性能加速。

## 测试设计

在 `test_llm_agent.py` 新增或调整以下测试：

1. **同一轮两个工具调用**：模拟两个独立工具；验证执行顺序、两个 `tool_call_id`、两个 tool 消息及最终回答。
2. **同一轮两个工具后继续一轮**：验证总次数跨轮累计，并保持三次上限。
3. **整批超过剩余额度**：已执行两次后，模型一次请求两个工具；验证两个工具都不执行且不会继续请求模型。
4. **批内工具失败**：第一个工具成功、第二个工具无效；验证第二个工具失败后停止，不执行后续调用且不请求模型。
5. 保留连续单工具调用、最终无工具请求、API 错误及参数校验测试。

完整测试集应继续通过；README 中的功能说明、流程和测试数量需与最终实现一致。

## 验收标准

- 模型同一轮返回多个合法工具调用时，Agent 能依序执行并正确回传所有结果。
- 单次请求累计工具执行次数永远不超过 3。
- 批量调用超过额度时不会执行任何工具。
- 工具失败时 Agent 立即停止，不产生额外模型请求。
- 全部测试通过，`git diff --check` 没有格式错误。
