# 多步骤单工具 Agent 设计

## 目标

将 `LLMToolAgent` 从“最多调用一次工具”的流程升级为“最多连续调用三次工具”的循环流程。

用户可以提出有先后依赖的请求，例如先把文本转为大写，再统计结果中的英文单词数量。模型每轮只能请求一个工具；Python 负责校验并执行该工具，再将结果交回模型决定下一步。

## 范围

本次只改造 DeepSeek Tool Calling 的控制流程：

- 保留现有三个工具：`upper_text`、`count_words`、`summarize_text`。
- 每一轮最多允许一个工具调用。
- 每次用户请求最多执行三次工具调用。
- 模型一次返回多个工具调用时，继续拒绝，不实现并行或同轮多工具。
- 不增加联网、文件访问、记忆、并行执行或新工具。

## 运行流程

```text
用户请求
  ↓
带工具 Schema 调用模型
  ↓
模型直接回答？──是──→ 返回回答
  │否
  ↓
校验单个工具调用 → 执行工具 → 追加 assistant/tool 消息
  ↓
工具调用次数小于 3？──是──→ 再次带工具 Schema 调用模型
  │否
  ↓
不带工具 Schema 调用模型，强制生成最终回答
```

例如：

```text
用户：先把 hello agent 转为大写，再统计单词数
第 1 轮：upper_text("hello agent") → "HELLO AGENT"
第 2 轮：count_words("HELLO AGENT") → 2
第 3 轮：模型输出最终回答
```

## 实现设计

### `llm_agent.py`

`LLMToolAgent.run()` 使用循环维护消息历史和已执行工具次数。

1. 首次请求保留系统提示词、用户消息、`TOOL_SCHEMAS` 和 `tool_choice="auto"`。
2. 每次模型请求单个工具时，复用 `_run_tool()` 进行白名单、JSON 和 `text` 类型校验。
3. 成功执行后，把模型的 assistant 消息和 `role="tool"` 的工具结果加入 `messages`。
4. 少于三次工具调用时，继续发送带工具 Schema 的模型请求。
5. 第三次工具完成后，发送一次不带 `tools` 和 `tool_choice` 的模型请求，要求模型仅生成最终回答。
6. 任意模型请求异常继续返回 `API_CALL_ERROR_MESSAGE`；工具校验错误立即返回已有错误信息。

### 工具调用约束

- `tool_calls` 为空：直接返回模型文本。
- `tool_calls` 数量不是 1：返回 `MULTIPLE_TOOL_CALLS_MESSAGE`，不执行工具。
- 未知工具、无效 JSON、缺失或非字符串 `text`：保持现有中文错误信息，并停止循环。

## 测试设计

在 `test_llm_agent.py` 新增：

1. **连续两次工具调用**：依次模拟 `upper_text`、`count_words` 和最终文本回答；验证两个工具结果都被正确追加，模型调用总数为三次。
2. **三次工具上限**：模拟三次工具调用；验证三个工具均执行后，第四次模型请求没有 `tools` 和 `tool_choice`，并返回最终文本。

保留已有测试：直接回答、初始和最终 API 异常、单次工具调用、同轮多工具拒绝、未知工具和参数错误。

## 文档更新

更新 `README.md` 的流程图、当前限制和测试数量，说明 Agent 支持连续三轮单工具调用，但不支持同轮多个工具调用。

## 验收标准

- 所有测试通过。
- 单次请求可连续执行两次有依赖的工具。
- 工具执行次数永远不超过三次。
- 达到上限后，最终模型请求不再提供工具。
- 格式检查 `git diff --check` 无代码格式错误。
